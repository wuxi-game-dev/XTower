# 04｜输入、物理与导航

本章追踪[00｜启动时间线](00-从双击到第一帧.md)里“玩家按下右方向键”到“角色真的向右移动”的因果链：

```text
键盘硬件/操作系统事件
  → Godot 的 DisplayServer/Input 把它变成 InputEvent 和动作状态
  → Viewport 将事件给 UI 与场景节点
  → 角色在 _PhysicsProcess 中读取 move_right
  → 设置 CharacterBody2D.Velocity 并调用 MoveAndSlide()
  → 物理服务按碰撞形状计算允许的位移
  → 角色 GlobalPosition 改变
  → 下一次渲染根据相机和新位置画出角色
```

`InputEvent` 是一次“发生了按下/松开”；`Input.IsActionPressed()` 是“此刻是否仍按住”。保持右键 1 秒只产生少数事件，却可以在几十个物理步中持续读取为 `true`。物理服务不负责替你决定按右键要走多快；它负责在你请求运动后处理碰撞约束。

## 1. 输入：动作优先于设备按键

在 Project Settings → Input Map 定义 `move_left`、`move_right`、`jump`、`attack` 等动作，再给动作绑定键盘、手柄或鼠标。游戏逻辑读取动作，不直接依赖某个按键。这样换键位和支持手柄更容易。

```csharp
using Godot;

public partial class Player : CharacterBody2D
{
    [Export] public float RunSpeed { get; set; } = 220f;
    [Export] public float JumpSpeed { get; set; } = 420f;
    [Export] public float Gravity { get; set; } = 1000f;

    public override void _PhysicsProcess(double delta)
    {
        Vector2 velocity = Velocity;
        velocity.X = Input.GetAxis("move_left", "move_right") * RunSpeed;

        if (!IsOnFloor())
            velocity.Y += Gravity * (float)delta;
        else if (Input.IsActionJustPressed("jump"))
            velocity.Y = -JumpSpeed;

        Velocity = velocity; // 速度单位是像素/秒，此处不要再乘 delta。
        MoveAndSlide();
    }
}
```

上述示例需要 `Player` 下有 `CollisionShape2D`，并在 Input Map 建立三个动作。它是教学版控制器，生产项目还要考虑可变跳高、土狼时间、斜坡、移动平台等。

## 2. 输入事件的路径

设备事件进入 Viewport 后，可能由 `_Input()`、UI 的 `_GuiInput()`、快捷键处理和 `_UnhandledInput()` 等阶段消费。常用原则：

- `_Input()`：需要优先看到原始事件的系统，例如输入重绑定。
- `Control._GuiInput()`：按钮、菜单、拖拽等 UI 内部交互。
- `_UnhandledInput()`：UI 没处理后，世界中的点击和操作。
- `Input.IsActionPressed()`：持续状态轮询，例如角色移动。
- `GetViewport().SetInputAsHandled()`：明确停止后续传播。

`Control.MouseFilter` 会决定鼠标事件是否被 UI 吞下或继续传递。界面盖在游戏上时，点击穿透问题多半先检查它和输入回调选择。[输入事件流程](https://docs.godotengine.org/en/stable/tutorials/inputs/inputevent.html)

**一次具体点击**：鼠标落在暂停按钮上 → 根 Window/Viewport 得到鼠标事件 → Button 的 GUI 输入命中并发出 `Pressed` → 事件被标为已处理 → 游戏世界的 `_UnhandledInput()` 不应再把这次点击当作开火。若你在 `_Input()` 中直接处理开火，它可能在 UI 之前就反应；这是输入层级设计错误，而不是物理故障。

## 3. 物理对象怎么选

| 节点 | 适合场景 | 移动方式 |
| --- | --- | --- |
| `StaticBody2D/3D` | 墙、地面、固定障碍 | 通常不在运行中频繁移动 |
| `AnimatableBody2D/3D` | 可移动平台、被动画驱动的实体 | 由代码或动画移动 |
| `CharacterBody2D/3D` | 玩家、代码控制的敌人 | 设置 `Velocity`，调用 `MoveAndSlide()` 或 `MoveAndCollide()` |
| `RigidBody2D/3D` | 箱子、弹球、由物理模拟的物体 | 施加力/冲量，让物理引擎主导 |
| `Area2D/3D` | 拾取范围、攻击判定、触发器 | 监听进入/退出，不提供普通实体的阻挡 |

每个物理对象通常还需要对应的 `CollisionShape2D/3D`。`Sprite2D` 只负责显示，不会因为图片看起来有边界就自动产生碰撞。复杂多边形不是越精细越好；先用简单形状验证玩法。

## 4. Collision Layer 与 Mask

记住两句话：**Layer = 我属于哪些层；Mask = 我检测哪些层**。例如玩家属于 `Player` 层，检测 `World` 和 `Enemy`；攻击范围属于 `Attack` 层，检测 `Enemy`。这与渲染的 CanvasLayer 或 Camera Cull Mask 无关。

出现“明明重叠却不触发”时，依次检查：节点类型、CollisionShape 是否启用、Layer/Mask 是否匹配、`Area2D.Monitoring`、信号是否订阅、对象是否在同一个物理空间。给物理层命名比记“第 7 位”可靠。[物理与层掩码](https://docs.godotengine.org/en/stable/tutorials/physics/physics_introduction.html)

## 5. 射线与空间查询

射线适合地面探测、视线遮挡、枪械命中。`RayCast2D/3D` 节点适合持续查询；`DirectSpaceState` 适合按需查询。物理空间查询通常放在 `_PhysicsProcess()` 或其他安全的物理时点。结果可能为空，所以别直接强转并访问。

```csharp
using Godot;

public partial class GroundSensor : Node2D
{
    public override void _PhysicsProcess(double delta)
    {
        var ray = GetNode<RayCast2D>("RayCast2D");
        if (ray.IsColliding())
            GD.Print($"地面: {ray.GetCollider()}");
    }
}
```

## 6. 导航与物理不是一回事

导航系统负责规划“从这里到那里走哪条路”，物理系统负责“当前位置能否穿过墙、实际如何移动”。2D 可用 `NavigationRegion2D` 提供导航区域、`NavigationAgent2D` 提供路径上的下一点；3D 有对应节点。Agent 不会自动移动角色，你仍需按路径点设置速度，并处理碰撞和避障。

```text
目标位置 → 导航求路径 → 下一路径点 → 自己控制 CharacterBody2D 移动 → 物理检测
```

动态障碍、重烘焙导航网格和大量 Agent 是进阶话题。第一步先做静态导航区域，让一个角色走到点击位置。[导航概览](https://docs.godotengine.org/en/stable/tutorials/navigation/navigation_introduction_2d.html)

导航的输出通常是“下一目标点”，物理的输出是“本步实际移动到了哪里”。两者不同：导航计划直穿一扇门，但门突然关闭时，碰撞仍应阻止角色穿门；你再决定重算路径还是等待。

## 7. 常见误区

- `RigidBody` 被模拟器控制，别每帧直接写位置来“纠正”它。
- `Area2D` 的检测与“实体互相推开”是不同功能。
- `MoveAndSlide()` 使用速度和物理步；直接改 `Position` 会绕开角色运动 API 的碰撞响应。
- 想做完全确定的回放或锁步联网，需要另行设计；Godot 默认物理不保证跨环境确定性。
