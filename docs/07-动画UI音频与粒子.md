# 07｜动画、UI、音频与粒子

这些系统的共同点是：它们主要呈现状态，也可能反过来通过信号触发逻辑。让“规则”和“表现”有清楚的边界：生命值变化是规则，血条变短、受伤动画和音效是表现。

## 1. 三种常见动画工具

| 工具 | 适合 | 不适合 |
| --- | --- | --- |
| `AnimatedSprite2D` + `SpriteFrames` | 帧图片切换、像素角色行走/攻击 | 大量任意属性同时编排 |
| `AnimationPlayer` | 多属性时间轴、动画事件、过场、Sprite 帧/位置/颜色 | 复杂条件状态图本身 |
| `Tween` | 临时且短暂的数值变化，例如淡入、受伤闪光 | 长篇可复用的角色动画 |

复杂角色状态切换可加 `AnimationTree`，让状态机或混合树管理走路、攻击、受伤。先确认“状态由谁决定”：通常由角色逻辑决定播放哪个动画，而不是让动画时间轴直接成为业务规则的唯一来源。动画方法轨道可以触发事件，但需要避免重复调用、被中断或跳帧导致状态不一致。

```csharp
using Godot;

public partial class DoorVisual : Node2D
{
    public void Open()
    {
        // 先在编辑器创建名为 Open 的动画。
        GetNode<AnimationPlayer>("AnimationPlayer").Play("Open");
    }
}
```

## 2. UI：Control、锚点、Container

Godot 的 UI 不是普通 `Node2D` 布局。`Control` 有矩形尺寸、锚点、偏移、最小尺寸、焦点和 GUI 输入。`Container` 自动排列子控件，例如 `HBoxContainer`、`VBoxContainer`、`GridContainer`、`MarginContainer`。被 Container 管理的子控件位置/尺寸可能由容器重算，手动拖动它们往往不会按预期保留。

```text
CanvasLayer
└─ MarginContainer（贴合屏幕边缘，提供外边距）
   └─ VBoxContainer
      ├─ Label（关卡名）
      ├─ ProgressBar（生命）
      └─ Button（暂停）
```

`CanvasLayer` 让 HUD 脱离相机卷动，`Control` 的锚点/Container 负责适应分辨率。给按钮订阅 `Pressed` 信号；鼠标事件被 UI 消费后，世界点击通常在 `_UnhandledInput()` 中不再收到。手柄/键盘导航还要配置焦点邻居和主题状态。[UI 文档](https://docs.godotengine.org/en/stable/tutorials/ui/)

### 主题与样式

`Theme` 资源统一控件字体、颜色、样式盒。优先建立少量全局主题规则，再在必要处局部覆盖。图片 UI 需要考虑九宫格拉伸、DPI 与不同语言文本长度。UI 有时要更新每帧，但生命/金币类数据更适合在值变化时用信号推送。

## 3. 音频：Stream、Player、Bus

`AudioStreamPlayer` 播放不随世界位置变化的声音（UI、音乐）；`AudioStreamPlayer2D/3D` 提供空间位置与衰减。`AudioStream` 是音频资源；`Audio Bus` 负责分组、音量和效果，例如 `Master`、`Music`、`SFX`、`UI`。调节设置中的音乐音量通常应改 Bus，而不是遍历所有播放器。

```csharp
using Godot;

public partial class ClickSound : Button
{
    public override void _Ready()
    {
        Pressed += () => GetNode<AudioStreamPlayer>("ClickPlayer").Play();
    }
}
```

长音乐与短音效的导入和压缩策略不同。大量同时播放的相同音效可能需要控制并发和音量，避免声音堆叠。[音频总览](https://docs.godotengine.org/en/stable/tutorials/audio/)

## 4. 粒子和屏幕特效

`GPUParticles2D/3D` 适合大量短命视觉粒子，例如灰尘、火花、烟雾；CPU 粒子在特定平台或需求下有用途。粒子通常只是表现，不应让每颗火花承担命中判定。命中由物理/逻辑决定，成功命中后再生成粒子。

全屏闪烁、模糊、色调变化通常涉及 CanvasItem Shader、Viewport 纹理或环境后处理。先用一个局部特效验证视觉目标，再扩大到全屏；全屏片元运算量跟分辨率直接相关。

## 5. 光照与阴影

2D 中 `PointLight2D`、`DirectionalLight2D` 与遮挡体可以构造灯光和阴影；3D 中常见有 Directional、Omni、Spot、环境光与阴影贴图。2D 图片若没有法线信息，灯光能改变整体明暗，但无法自然知道画中“鼻子朝哪边凸出”；法线贴图可提供表面方向信息。[2D 光照与阴影](https://docs.godotengine.org/en/stable/tutorials/2d/2d_lights_and_shadows.html)

## 6. 表现系统的连接方式

```text
Health.Damage(10)
  ├─ 修改真实生命值
  ├─ 发出 HealthChanged 信号 → HUD 更新进度条
  ├─ 发出 Hit 信号 → Sprite 播放闪红 Tween
  └─ 发出 Died 信号 → 播放死亡动画/音效，完成后移除节点
```

这样关掉粒子、换 UI 框架或替换动画时，伤害规则不用重写。对 Unity 开发者来说，这类似把 Gameplay State 与 Presentation 分离，但在 Godot 中通常用节点和信号表达。
