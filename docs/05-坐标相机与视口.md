# 05｜坐标、相机与视口

## 1. 先分清“位置在哪个坐标系”

渲染与点击错误最常见的原因，是把局部、世界、画布、视口和屏幕坐标混用。

| 坐标 | 含义 | 典型用途 |
| --- | --- | --- |
| 局部 Local | 相对父节点 | 子节点 `Position` |
| 全局/世界 Global | 相对游戏世界 | `GlobalPosition`、实体间距离 |
| 画布 Canvas | 2D 绘制空间，受画布变换影响 | 2D 世界与 CanvasLayer |
| 视口 Viewport | 某个 Viewport 的可绘制区域 | 鼠标视口位置、屏幕 Shader |
| 窗口/屏幕 Screen | 物理窗口上的位置 | 多窗口、窗口坐标 |

`Node2D.Position` 是相对父节点；`GlobalPosition` 是全局位置。父节点移动，子节点的局部 `Position` 可以不变，但 `GlobalPosition` 会变。缩放和旋转也会继承。

在 2D 中，把位置从本地变到屏幕，概念上是：

```text
局部点 → 节点及父节点变换 → 世界/画布点 → 相机与 CanvasLayer 变换
       → Viewport 拉伸与窗口变换 → 屏幕点
```

这是矩阵/仿射变换链。顺序不能随意交换。实际开发优先调用 Godot 的坐标转换 API，不要手算所有变换。[Viewport 和 Canvas 变换](https://docs.godotengine.org/en/stable/tutorials/2d/2d_transforms.html)

## 2. Camera2D 不是“移动世界对象”

`Camera2D` 决定 2D 世界在 Viewport 中的观察中心、旋转、缩放和边界。它改变的是画布变换，世界对象的 `GlobalPosition` 不因此变化。

忽略旋转、平滑、限制和拉伸时，可用一个直觉公式：

```text
屏幕位置 ≈ 视口中心 + (世界位置 − 相机中心) × 缩放
```

相机右移时，静止对象看起来左移；相机缩放为 `Vector2(2,2)` 时，同样的世界距离大致占两倍屏幕像素。真实工程里还要考虑锚点模式、Viewport 和窗口拉伸，不能用这个简化式替代 API。

常用属性：`Position/GlobalPosition`、`Zoom`、`LimitLeft/Right/Top/Bottom`、`PositionSmoothingEnabled`、`PositionSmoothingSpeed`。直接把相机设为玩家子节点适合最简单跟随；需要预测、锁定区域或关卡边界时使用独立相机节点。

```csharp
using Godot;

public partial class FollowCamera : Camera2D
{
    [Export] public Node2D Target { get; set; } = default!;

    public override void _Process(double delta)
    {
        // 最简单的跟随；平滑可以改用 Camera2D 自带属性。
        if (GodotObject.IsInstanceValid(Target))
            GlobalPosition = Target.GlobalPosition;
    }
}
```

相机平滑时，节点的 `GlobalPosition` 与此刻真正显示的画面中心可能不同；用 `GetScreenCenterPosition()` 检查显示中心。[Camera2D API](https://docs.godotengine.org/en/stable/classes/class_camera2d.html)

## 3. HUD 为什么常放 CanvasLayer

假设世界中有玩家血条和屏幕角落的总生命 UI。前者跟随玩家，属于世界；后者必须固定在窗口角落，不应该跟着相机缩放、滚动。把后者放在 `CanvasLayer` 下，再用 `Control` 的锚点与容器布局。

```text
Game : Node2D
├─ World : Node2D
│  ├─ Player
│  └─ Camera2D
└─ HUD : CanvasLayer
   └─ MarginContainer
      └─ HealthLabel
```

CanvasLayer 的层级还可控制前后覆盖。它不是物理碰撞层，也不是 3D 的可见性层。要让 UI 适配宽屏、缩放和不同 DPI，更多依赖 `Control` 的锚点/Container，而不是写死 `Position`。

## 4. 鼠标位置转世界位置

在 `Node2D` 脚本中，`GetGlobalMousePosition()` 通常直接给出当前画布中的全局鼠标位置，适合“在鼠标处放置单位”。`GetViewport().GetMousePosition()` 是视口坐标，不能在相机滚动后直接拿来当世界位置。

```csharp
using Godot;

public partial class ClickMarker : Node2D
{
    public override void _UnhandledInput(InputEvent @event)
    {
        if (@event.IsActionPressed("select"))
        {
            GlobalPosition = GetGlobalMousePosition();
            GetViewport().SetInputAsHandled();
        }
    }
}
```

先在 Input Map 创建 `select` 并绑定鼠标左键。若事件发生在独立 `SubViewport` 或复杂 CanvasLayer 中，要按对应 Viewport 的变换处理。

## 5. Camera3D：视图矩阵与投影矩阵

3D 中可以把顶点从模型坐标变到最终裁剪坐标概括为：

```text
clip_position = Projection × View × Model × local_position
```

- **Model**：物体自身的位置、旋转、缩放。
- **View**：从世界转换到相机坐标；等价于相机变换的逆。
- **Projection**：从相机空间投影到可显示区域。

透视投影使远物更小；正交投影保持尺寸关系，适合策略游戏、等距视角与某些 2.5D 效果。Godot 3D 的常见约定是 Y 向上，摄像机默认朝局部 **−Z** 方向观察。相机的 Near/Far 裁剪面决定可见深度区间，Cull Mask 决定哪些 3D 可见层被绘制。它们不代替物理碰撞的 Layer/Mask。

鼠标在 3D 中只有屏幕点，没有唯一的世界点；要把屏幕点投成射线，再与地面平面或物理对象求交。`Camera3D.ProjectRayOrigin()` 和 `ProjectRayNormal()` 是常用入口。[Camera3D API](https://docs.godotengine.org/en/stable/classes/class_camera3d.html)

## 6. Viewport 是渲染目标，也是边界

根 `Window` 本身是 Viewport。`SubViewport` 可以把一套场景渲染为纹理，常用于小地图、角色预览、监视器画面、分屏。它有自己的相机、大小、环境和输入传播问题；`SubViewportContainer` 可帮助显示并转发输入。

```text
3D/2D 场景 → SubViewport → ViewportTexture → TextureRect 或 3D 材质
```

这是 Unity `RenderTexture` 的近似路线。多一个 Viewport 可能意味着多画一次场景，性能需要实测。

## 7. 分辨率、缩放与像素风格

窗口尺寸、设计分辨率和游戏世界单位并非一回事。项目的窗口与 Stretch 设置影响内容在不同屏幕上的缩放和黑边。像素美术还要关注贴图过滤、整数缩放、相机子像素移动和 UI 字体清晰度。先确定期望的画面比例和像素风格，再调整 Stretch；别在每个节点上各自补一套缩放公式。
