# 08｜数据、调试、性能与发布

前面讲的是进程从启动到重复绘制。本章讲进程之外的状态与诊断：资源从哪里读、存档写到哪里、某一帧慢在哪里、把项目变成别人可以双击的程序。回看[00｜启动过程](00-从双击到第一帧.md)时，导出包和项目设置正是“进程启动后引擎要读什么”的答案。

## 1. `res://` 与 `user://`

`res://` 是项目资源路径，适合场景、脚本、贴图、配置模板。导出后的资源可能被打包，不要把它当作普通可写目录。`user://` 是应用的用户数据目录，适合设置与存档；具体系统位置由平台决定。网络数据和可修改存档仍需做格式、版本及错误处理。

## 2. 一份最小 JSON 存档

示例演示数据流，不包含加密、防作弊或版本迁移。存档模型使用普通 C# 数据类，读写通过 Godot `FileAccess`；避免直接序列化整个场景树。

```csharp
using Godot;
using System.Text.Json;

public sealed class SaveData
{
    public int Version { get; set; } = 1;
    public int Level { get; set; } = 1;
    public int Coins { get; set; }
}

public static class SaveService
{
    private const string Path = "user://save.json";

    public static void Save(SaveData data)
    {
        using var file = FileAccess.Open(Path, FileAccess.ModeFlags.Write);
        if (file is null)
        {
            GD.PushError($"存档写入失败：{FileAccess.GetOpenError()}");
            return;
        }

        file.StoreString(JsonSerializer.Serialize(data));
    }

    public static SaveData Load()
    {
        if (!FileAccess.FileExists(Path)) return new SaveData();
        using var file = FileAccess.Open(Path, FileAccess.ModeFlags.Read);
        if (file is null)
        {
            GD.PushError($"存档读取失败：{FileAccess.GetOpenError()}");
            return new SaveData();
        }

        try
        {
            return JsonSerializer.Deserialize<SaveData>(file.GetAsText()) ?? new SaveData();
        }
        catch (JsonException ex)
        {
            GD.PushError($"存档格式错误：{ex.Message}");
            return new SaveData();
        }
    }
}
```

正式存档还需考虑写入中断、备份、格式版本升级和数据校验。若要 AOT/裁剪，`System.Text.Json` 的反射序列化可能需要源生成配置。保存“状态数据”比保存整棵运行时节点树更可控。[保存游戏](https://docs.godotengine.org/en/stable/tutorials/io/saving_games.html)

## 3. 资源导入与缓存

把图片或音频放入项目后，Godot 会导入并生成运行时使用的数据。导入设置会决定过滤、压缩、切片等效果。源资产和必要的导入配置应纳入版本控制；`.godot/` 是生成缓存，通常忽略。出现“贴图为什么糊了/边缘漏色”，先看 Import 面板、过滤与压缩，而不必立刻写 Shader。[导入资源](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_images.html)、[版本控制](https://docs.godotengine.org/en/stable/tutorials/best_practices/version_control_systems.html)

## 4. 调试时看什么

| 现象 | 优先检查 |
| --- | --- |
| 节点找不到 | Remote 场景树、节点路径、实例加入树的时机 |
| 画面不可见 | Visible、相机范围、CanvasLayer、Z/深度、贴图导入 |
| 事件不触发 | 信号连接、Input Map、MouseFilter、Layer/Mask |
| 运动抖动 | `_Process` 与 `_PhysicsProcess` 混用、相机更新、插值设置 |
| 帧率下降 | Profiler 中脚本、物理、渲染帧时间；目标硬件实测 |

编辑器的 Debugger 提供错误、断点、远程变量和监视；Profiler 显示时间开销；Monitors 可观察绘制调用、对象与内存。先定位 CPU、GPU、物理还是资源问题，再优化。`GD.Print()` 适合小范围验证，持续每帧打印会干扰性能和阅读。

## 5. 性能的基本方法

1. **定义目标**：平台、分辨率、目标帧率。例如 60 FPS 的总帧时间预算约为 16.7 ms。
2. **构造可重复场景**：敌人数量、粒子数量、相机位置固定。
3. **测量**：区分脚本耗时、物理耗时、渲染耗时和资源加载卡顿。
4. **改一个瓶颈**：减少高频全树查询、过多物理形状、昂贵全屏效果或重复 Viewport。
5. **复测**：记录修改前后的相同场景结果。

不要预设“节点多必定慢”“C# 必定比 GDScript 快”“一个 Shader 一定比多个节点快”。成本取决于调用次数、数据量、GPU 覆盖面积和平台。[性能优化总览](https://docs.godotengine.org/en/stable/tutorials/performance/)

## 6. 导出与发布

Godot 的 Editor 与运行时 Export Templates 是不同交付物。导出前要在 Editor → Manage Export Templates 安装匹配版本模板，Project → Export 配置平台预设。C# 项目还需要确认目标平台的 .NET 支持与打包方式；桌面通常最直接，移动和 Web 的限制应按当前版本官方文档核实。[导出项目](https://docs.godotengine.org/en/stable/tutorials/export/)、[C# 平台支持](https://docs.godotengine.org/en/stable/tutorials/scripting/c_sharp/)

可交付构建不等于“本机编辑器内能运行”。至少在干净目录和目标设备上检查启动、资源路径大小写、输入、分辨率、声音、存档与关闭流程。

## 7. 测试边界

纯规则可写成不依赖场景树的 C# 类并做单元测试；场景实例化、信号、物理和渲染要在 Godot 运行环境中验证。别用大量只检查常量或属性赋值的测试替代实际试玩。一个有效的最小集是：规则测试、运行时场景烟测、手动可重复试玩清单。
