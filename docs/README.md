# Godot 4 从双击到画面：Unity 开发者手册

这份资料独立于当前游戏项目。它用 Godot 4 .NET/C# 讲解，但重点不是 C# 语法，而是**机器怎样启动游戏、引擎怎样反复推进世界、画面怎样送到屏幕**。Unity 对照用于帮你定位熟悉的概念。

## 第一站：只读这一篇

**[00｜从双击到第一帧](00-从双击到第一帧.md)**。从操作系统创建进程开始，依次追踪 Godot 初始化、请求创建窗口、加载项目与主场景、节点生命周期、第一轮输入/物理/普通帧、GPU 绘图、画面呈现和退出。文末有一个可在空 Godot .NET 项目里运行的 `BootProbe` 实验。先亲眼看见日志顺序和 Remote 场景树，再看其他章节。

这里有一个必须先分清的事实：**双击先产生进程；Godot 向操作系统请求窗口；窗口出现后，场景树和渲染管线才让游戏画面显示出来。** `SceneTree` 驱动节点，你不需要自己在 C# 写无限 `while` 循环。

## 用一句话串起来

```text
OS 启动进程 → Godot 建窗口/引擎服务 → SceneTree 装入主场景
→ 输入改变节点状态 → 固定物理步与普通帧推进状态
→ 相机/Viewport 决定画哪里 → 渲染服务/GPU 生成像素
→ 显示系统把图像呈现到窗口 → 重复直到退出
```

每章只在这一条链上展开一两个环节。阅读时不断问“谁创建了它、谁调用它、它持有哪份状态、结果交给谁”。这是理解引擎的主线。

## 读法与验证

1. 在空的 Godot 4 .NET 项目完成第 00 章实验，观察日志、窗口和 Remote 场景树。
2. 每读一章，尝试画出这个模块在上述因果链里的入口和出口。
3. 代码片段依赖各章写明的场景节点、输入动作和资源配置；只复制 C# 文件而不搭场景，通常不能运行。
4. 文档解释稳定的 Godot 4 概念。具体版本 API 以编辑器自动补全和[官方类参考](https://docs.godotengine.org/en/stable/classes/)为准；Godot 3 教程不可直接照搬。

官方入口：[SceneTree](https://docs.godotengine.org/en/stable/tutorials/scripting/scene_tree.html)、[渲染架构](https://docs.godotengine.org/en/stable/engine_details/architecture/internal_rendering_architecture.html)、[C#/.NET](https://docs.godotengine.org/en/stable/tutorials/scripting/c_sharp/)。
