# 03｜场景、节点、资源与通信

在[00｜启动时间线](00-从双击到第一帧.md)中，窗口和引擎服务先准备好，随后 Godot 才加载 Autoload 与主场景。本章拆开“加载一个 `.tscn` 文件”究竟做了什么。`.tscn` 是磁盘上的描述，`PackedScene` 是可实例化的资源，节点树是运行时对象，三个阶段不能混成一个。

```text
磁盘/导出包中的 Main.tscn
    ↓ ResourceLoader.Load<PackedScene>()
内存中的 PackedScene 模板
    ↓ Instantiate()
尚未进入世界的 Node 树
    ↓ AddChild() 到根 Window 或某个场景节点
活跃场景树：_EnterTree、_Ready、输入/更新/绘制开始生效
```

把模板载入内存不会自动触发 `_Ready()`；单纯 `Instantiate()` 也不会让对象被当前 Viewport 画出。必须进入对应场景树。一个主场景加入根 `Window` 后，`GetTree().CurrentScene` 才指向当前主场景根节点。Autoload 的节点在主场景之前加入，可供主场景的脚本使用。

## 1. 以“可复用单元”设计场景

一个场景不等于一个关卡。角色、子弹、门、血条、暂停菜单都可以各自保存为 `.tscn`。把它们组合成更大的场景，形成“从小块搭大块”的结构。

```text
Level.tscn
└─ Level : Node2D
   ├─ World : Node2D
   │  ├─ Player（Player.tscn 实例）
   │  ├─ Enemies : Node2D
   │  └─ Camera2D
   └─ HudLayer : CanvasLayer
      └─ Hud（Hud.tscn 实例）
```

父子关系意味着生命周期与变换继承：父节点被释放，子节点也随之退出；`Node2D` 子节点的位置默认相对父节点。复杂玩法不要只有一个根脚本；也不必为每一个数值都建节点。节点负责行为和可观察的结构，普通 C# 类可承担纯计算。

## 2. 实例化与释放

在 Inspector 给 `PackedScene` 赋值，然后在运行时实例化。以下示例假定父节点有名为 `Enemies` 的 `Node2D`，敌人场景根节点也是 `Node2D`：

```csharp
using Godot;

public partial class EnemySpawner : Node2D
{
    [Export] public PackedScene EnemyScene { get; set; } = default!;
    [Export] public Node2D SpawnPoint { get; set; } = default!;

    public void Spawn()
    {
        var enemy = EnemyScene.Instantiate<Node2D>();
        GetNode<Node2D>("Enemies").AddChild(enemy);
        enemy.GlobalPosition = SpawnPoint.GlobalPosition;
    }
}
```

`AddChild()` 后节点进入树，才有可靠的 `GetTree()`、全局变换和生命周期。删除节点通常用 `QueueFree()`，它安排在当前帧安全时机释放；不要继续长期保存已排队释放的引用。换整个关卡可使用 `GetTree().ChangeSceneToPacked(...)` 或场景路径版本，并检查跨场景数据由谁持有。

## 3. 查找节点：路径、导出引用、组

- **固定的子节点**：`GetNode<Sprite2D>("Visual/Sprite2D")`，或 `[Export] public Sprite2D Visual { get; set; }` 后在 Inspector 拖入。路径短且结构稳定时好用。
- **动态对象集合**：加入组，例如 `enemies`；`GetTree().GetNodesInGroup("enemies")` 适合偶尔查询。高频逻辑可维护自己的集合。
- **跨系统关系**：信号或明确的服务引用，比全树搜索更容易维护。

组相当于轻量标签，不是带强类型的接口。组名拼写错误通常到运行时才暴露；关键协议可封装常量。

## 4. Resource：数据和资产

贴图 `Texture2D`、音频 `AudioStream`、碰撞形状 `Shape2D`、材质 `Material`、`PackedScene` 都是资源。自定义资源适合“设计时配置”，例如：

```csharp
using Godot;

[GlobalClass]
public partial class WeaponData : Resource
{
    [Export] public string DisplayName { get; set; } = "Basic";
    [Export] public float Damage { get; set; } = 10f;
    [Export] public float CooldownSeconds { get; set; } = 0.5f;
    [Export] public Texture2D? Icon { get; set; }
}
```

创建 `.tres` 后，多个武器节点可以引用同一个 `WeaponData`。这很像 Unity 的 `ScriptableObject`。**配置与运行时状态分开**：`Damage` 可放 Resource，“这把武器当前还有 0.2 秒冷却”应放节点或普通运行时对象。多个实例引用同一资源时，对资源的运行时修改可能一起生效；要独立修改就 `Duplicate()` 或启用合适的本地化资源设置，并确认嵌套资源是否也需要复制。

## 5. 信号：把“发生了什么”与“谁来响应”分开

`Button.Pressed`、`Timer.Timeout`、`Area2D.BodyEntered` 都是内置信号。C# 中常以事件语法订阅；自定义信号需要 `[Signal]`，委托名以 `EventHandler` 结尾：

```csharp
using Godot;

public partial class Health : Node
{
    [Signal] public delegate void DiedEventHandler();

    [Export] public int MaxValue { get; set; } = 100;
    public int Value { get; private set; }

    public override void _Ready() => Value = MaxValue;

    public void Damage(int amount)
    {
        if (Value <= 0 || amount <= 0) return;
        Value = Mathf.Max(0, Value - amount);
        if (Value == 0) EmitSignal(SignalName.Died);
    }
}
```

```csharp
using Godot;

public partial class Enemy : Node2D
{
    public override void _Ready()
    {
        GetNode<Health>("Health").Died += OnDied;
    }

    private void OnDied() => QueueFree();
}
```

Godot 对关联对象销毁时的许多信号连接会自动清理，但订阅 Autoload、长寿命对象或捕获外部状态的委托时，仍要认真管理退订和对象寿命。信号适合表达事件；需要返回值的同步查询通常直接调用方法。[C# 信号文档](https://docs.godotengine.org/en/stable/tutorials/scripting/c_sharp/c_sharp_signals.html)

## 6. Autoload：少量跨场景状态

在 Project Settings → Globals → Autoload 注册一个场景或脚本，它会在游戏启动时进入根树，跨场景持续存在。适合设置、存档服务、场景切换协调。不要把所有敌人、UI、输入和资源都塞进一个 Autoload；它会变成难以测试的全局大对象。

经验判断：若某对象只属于当前关卡，把它放在关卡场景；若确实要在切换关卡后继续存在，才考虑 Autoload。

## 7. 所有权与生命周期检查

代码添加的节点可能在编辑器中可见，却没有被保存进 `.tscn`；运行时 `AddChild` 和编辑器保存时的 `Owner` 是不同话题。初学时先把运行时动态生成与编辑器工具脚本分开。资源的引用计数与节点的 `QueueFree()` 也不同：节点退出树不等于 C# 托管引用立即消失；避免把已释放的 Godot 对象当作普通 .NET 对象继续使用。
