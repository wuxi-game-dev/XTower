# 01｜引擎全景：Godot 到底是什么

## 1. 五层心智模型

把 Godot 分成五层，复杂项目也容易定位问题：

| 层 | 做什么 | 常见对象 |
| --- | --- | --- |
| 项目与资源 | 存放场景、脚本、图片、音频及设置 | `project.godot`、`.tscn`、`.tres`、`res://` |
| 场景树 | 管理当前活着的对象及其生命周期 | `SceneTree`、`Node`、`Viewport` |
| 游戏逻辑 | 根据输入和状态改变世界 | C# 脚本、信号、组、计时器 |
| 引擎服务 | 执行物理、绘制、导航、音频 | PhysicsServer、RenderingServer、NavigationServer、AudioServer |
| 平台 | 窗口、设备输入、GPU、文件系统 | 操作系统、图形 API、驱动 |

最常见的控制方向是：平台产生输入 → SceneTree 把事件送给节点 → 脚本改变节点状态 → 引擎服务依据状态输出画面/声音。引擎服务通常通过节点封装使用；不要一开始就直接调用底层 Server API。

## 2. 与 Unity 的最短对照

| Unity | Godot | 需要注意的差异 |
| --- | --- | --- |
| Scene | Scene (`.tscn`) | Godot 场景也常用来定义一个可复用的角色或按钮 |
| GameObject + Components | 节点树 | 每个节点有明确类型；通过父子关系组合能力 |
| Prefab | `PackedScene` 实例 | Godot 的场景既能是关卡，也能像 Prefab 一样被实例化 |
| MonoBehaviour | 继承 `Node` 的脚本 | 一个节点通常挂一个脚本；其他能力由子节点承担 |
| ScriptableObject | `Resource` | 适合可序列化配置，默认可能在多个实例间共享 |
| Update / FixedUpdate | `_Process` / `_PhysicsProcess` | 两条更新通道的用途类似，具体调度不同 |
| Event / UnityEvent | Signal | 可由节点或脚本声明；C# 中可作为生成的事件使用 |
| Layer | Collision Layer / Mask | “我在哪层”和“我扫描哪些层”分别设置 |
| Canvas | `Control` 树、`CanvasLayer` | UI 布局主要由锚点与容器控制 |
| Camera / RenderTexture | `Camera2D`/`Camera3D`、`SubViewport` | 视口既是渲染目标，也是输入和场景的边界 |
| DontDestroyOnLoad 单例 | Autoload | 启动时加入根场景树，生命周期跨场景 |

这种对照只用于找入口。不要强行把所有 Godot 节点包装成 Unity 风格的组件系统；Godot 的核心组织单位是**一棵可实例化的节点树**。

## 3. Node、Scene、Resource 的边界

**Node** 是运行时实体，有父节点、子节点、生命周期和可选的处理回调。例如 `Sprite2D` 负责显示图片，`Timer` 负责计时，`AudioStreamPlayer` 负责播放声音。

**Scene** 是一棵节点树的保存模板。打开 `.tscn` 并不意味着它已在游戏中运行；把 `PackedScene` 实例加入当前树后，它才进入生命周期。场景可以嵌套场景。

**Resource** 是数据对象，常用于纹理、材质、声音、动画、配置。它不以节点身份进入场景树。多个节点引用同一资源时，修改该资源可能同时影响所有引用者；需要独立状态时复制资源或把运行时状态放在节点中。

```text
Enemy.tscn（模板）
└─ Enemy : CharacterBody2D（脚本：生命与移动）
   ├─ Sprite2D（贴图 Resource）
   ├─ CollisionShape2D（形状 Resource）
   ├─ AnimationPlayer（动画 Resource）
   └─ HurtArea : Area2D
```

`Enemy.tscn` 可以实例化十次；每个敌人拥有不同的生命值和位置，但可以共用同一张贴图。

## 4. 编辑器不是游戏本身

编辑器里的 Local 场景树是静态编辑内容；运行时的 Remote 场景树才展示真正实例化的节点。调试“为什么找不到节点”“为什么生成了两个敌人”时，先看 Remote 树。`res://` 指向项目资源目录；`user://` 指向应用可写的用户数据目录。`.godot/` 是生成缓存，不是业务资源。

## 5. 常用节点家族

| 家族 | 作用 | 例子 |
| --- | --- | --- |
| `Node` | 逻辑、计时与组织 | `Timer`、普通管理节点 |
| `Node2D` | 2D 位置/旋转/缩放 | `Sprite2D`、`Marker2D`、`Camera2D` |
| `Node3D` | 3D 变换 | `MeshInstance3D`、`Camera3D` |
| `Control` | UI 尺寸、锚点、焦点、输入 | `Button`、`Label`、`Container` |
| `CanvasLayer` | 独立 2D 画布层 | 固定在屏幕上的 HUD |
| `Viewport` | 渲染与输入边界 | 根窗口、`SubViewport` |

注意 `Control` 和 `Node2D` 都属于 2D 绘制体系，但一个负责界面布局，一个负责世界空间物体。不要用 `Sprite2D` 承担复杂 UI 布局，也不要用 `Control` 当物理角色。

## 6. 一句话判断该用什么

- 需要出现在世界里、有生命周期：考虑 **Node/Scene**。
- 需要复用的配置或资产：考虑 **Resource**。
- 要跨多个对象发通知：考虑 **Signal**。
- 要跨多个场景持续存在：少量使用 **Autoload**。
- 要画入另一张纹理或另一个窗口：考虑 **SubViewport**。
